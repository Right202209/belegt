# Belegt

## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 暂定名 | Belegt（德语“有据可查”） |
| 首个市场 | 德语区 50–1000 人的金属加工、汽车零部件二三级供应商 |
| 核心原则 | 零教学：知识来自系统、单据和历史答案；人只做封闭式确认 |
| 架构原则 | **LLM 负责理解，代码负责数字**；Agent 只经证据图协作 |
| 交付形态 | Open-core：开放标准层，商业化网络与托管 |


---

## 1. 目标客户与角色

画像不变：每年收到 20 份以上问卷；进口钢、铝，涉及 CBAM；没有专职 ESG 团队。

| 角色 | 诉求 | v2 新增触点 |
|---|---|---|
| 兼职合规负责人 | 少加班，不出错 | 审批收件箱 |
| 总经理 | 不丢订单，CBAM 不多交钱 | 成本差看板 |
| 销售 / 客户经理 | 客户催要时马上能给 | 销售助手 |
| 上游供应商（含非欧盟） | 看得懂、交得上 | **免费开源供应商端** |
| 客户方采购（V2） | 拿到结构化、可信的数据 | A2A / API 订阅 |
| **社区贡献者**（咨询顾问、行业协会、核查机构、开发者） | 复用映射，减少重复劳动 | 字典仓库、连接器 SDK |

## 2. 目标与非目标

**产品目标（12 个月）**
- 每份问卷的人工时长下降 ≥ 70%
- 有证据支撑的字段自动预填率 ≥ 80%
- 跨客户口径冲突在提交前 100% 拦截
- CBAM 进口量中使用默认值的比例下降 50%

**Agent 质量目标**
- 题目映射 Top-1 准确率 ≥ 90%，低置信度题目 100% 转人工
- 数字字段由模型生成的比例 = 0（系统强制）
- 单份问卷 LLM 成本 ≤ €[待定]，首稿生成时间 ≤ 30 分钟（100 题）

**开源目标**
- 数据点字典覆盖 ≥ 8 个模板，外部贡献映射 ≥ 30%
- 供应商端安装 / 注册数 ≥ [待定]（网络入口指标）

**非目标**
- 不做大企业 CSRD 报告编制
- 不出具第三方核查结论
- 不处理员工个人数据
- 不替代 ERP
- **不自研通用 Agent 框架**（基于 LangGraph、Temporal 等成熟组件）
- **不训练自有大模型**；“学习”就是更新答案库，不做微调

## 3. 核心机制

1. **数据点字典**：VSME、CDP、PACT / Catena-X、CBAM、EUDR、REACH / SCIP、CMRT、电池护照映射到同一套标准数据点。同一数据点只采集一次。**这一层开源。**
2. **证据图（Evidence Graph）**：所有答案、证据、计算、批准记录组成一张版本化的图，是唯一事实源。
3. **零教学学习**：导入历史答卷；缺数据时只问封闭式问题；人的每次批准或修改都写回证据图。
4. **确定性优先**：LLM 只做理解、路由、起草和解释；数字只能来自数据源或计算服务。

## 4. 多 Agent 架构

### 4.1 设计原则

| 原则 | 说明 |
|---|---|
| 能用代码就不用 Agent | 计算、一致性规则、有效期检查、审批路由都是确定性服务，由 Agent 当作工具调用 |
| 黑板协作 | Agent 之间不传自由文本，只读写证据图里带 schema 的对象 |
| 每份问卷一个持久化工作流 | 状态机可断点续跑、可重放、可审计（如 Temporal 或 LangGraph checkpoint） |
| 信任分区 | 接触外部内容的 Agent 在隔离区运行：不能外发，不能写正式数据，只产出候选 |
| 人在回路是一等节点 | 审批是工作流里的显式状态，不是事后检查 |
| 标准协议 | 工具和数据源走 MCP；企业间 Agent 互通走 A2A（V2） |
| 模型可替换 | 每个 Agent 都可以配置云端模型或自托管开源模型，私有化部署时也能用 |

### 4.2 拓扑

```
            ┌──────────── 守卫层（策略 / 预算 / 追踪 / 注入防护）────────────┐
外部内容 ─▶ [隔离区] 收件分拣 → 题目解析 → 上游回复审核
                         │ 候选对象（经 schema 校验）
                         ▼
                 ┌──── 证据图（唯一事实源）────┐
                 ▲        ▲          ▲         ▲
           证据挖掘   计算服务*   一致性审计*   法规雷达
                 │
                 ▼
           答案起草 → 审批路由* → [人工审批] → 填报 / 门户操作 → 归档学习
                                                      ↘ 销售助手（只读已批准数据）
* = 确定性服务
```

### 4.3 Agent 与服务清单

| 组件 | 类型 | 输入 → 输出 | 权限 | 人工节点 |
|---|---|---|---|---|
| 收件分拣 | LLM · 隔离 | 邮件 / 门户 → `Request`（类型、客户、截止日期、优先级） | 只读邮箱 | 低置信度时确认 |
| 题目解析 | LLM · 隔离 | 问卷文件 → `Mapping[]`（数据点、置信度、单位、期间） | 无工具 | 未映射题目 |
| 证据挖掘 | LLM + 规则 | 文档 / ERP → `Evidence[]`（字段、原文位置、有效期） | MCP 连接器只读 | 封闭式确认 |
| 计算服务 | **确定性** | 活动数据 + 因子版本 → `Calculation`（可复现） | 无 LLM | 方法论选择 |
| 一致性审计 | **确定性** + LLM 解释 | 答案集 → `Conflict[]` | 只读 | 冲突处理 |
| 答案起草 | LLM | 数据点 + 证据 → 文字类答案草稿 | 只读证据图 | 全部经审批 |
| 审批路由 | **确定性** | 答案 → 风险等级、审批人 | 策略引擎 | 是 |
| 上游追数 | LLM | 缺口 → 多语言请求 / 催办 | 外发仅限模板、白名单与频率上限 | 首次发送需确认 |
| 上游回复审核 | LLM · 隔离 | 供应商回复 → 候选数据 + 合理性标记 | 无工具 | 异常值 |
| 填报 / 门户操作 | 确定性回填 + 浏览器 Agent | 已批准答案 → 文件 / 门户提交 | 沙箱浏览器，仅在批准后 | 提交前确认 |
| 法规雷达 | LLM · 离线 | 法规源 → “下季度会被问到”清单 | 只读公开源 | 产品团队审核 |
| 销售助手 | LLM | 已批准数据 → 数据表、自助页 | 只读已批准对象 | 对外分享需确认 |
| 守卫 | **确定性** | 全部调用 | 横切 | 告警 |

### 4.4 数据契约（核心对象，均有版本）

`DataPoint` · `Request` · `Mapping` · `Evidence` · `Calculation`（含因子库版本、方法论版本、输入哈希）· `Answer`（值、单位、期间、口径、客户范围）· `Approval` · `Conflict` · `SupplierRequest`

规则：Agent 的输出必须通过 schema 校验才能写入；`Answer.value` 为数字时，必须引用 `Evidence` 或 `Calculation` 的 ID，否则拒绝写入。

### 4.5 失败与回退

| 情况 | 处理 |
|---|---|
| 置信度低于阈值 | 生成封闭式问题，转人工 |
| Agent 超过预算或步数 | 守卫中止，保存状态，转人工 |
| 两个 Agent 结论冲突 | 由一致性审计生成 `Conflict`，不自动裁决 |
| 连接器失效 | 降级为文档提取，并标记数据新鲜度 |
| 模型服务不可用 | 切换备用模型；确定性服务不受影响 |

### 4.6 Agent 评测

- 用试点客户的历史问卷建黄金集（脱敏），按 Agent 分别评测：映射准确率、提取字段准确率、冲突漏检率（目标 0）
- 每次改提示词、换模型都跑 CI 回归，指标下降不得合并
- 公共基准（公开模板加合成数据）随字典一起开源

### 4.7 安全

- 外部内容只进隔离区；隔离 Agent 没有工具，输出只是数据，不是指令
- 工具白名单加最小权限；对外发送走出口网关，有频率上限
- 全链路追踪：每一步都记录模型、提示词版本、token 成本和输入输出哈希

## 5. 开源策略

### 5.1 为什么开源

1. **信任**：计算可审计，核查机构和客户可以自己复算
2. **分发**：非欧盟上游供应商零成本使用，也是网络入口
3. **标准话语权**：字典成为事实标准，竞争对手越采用，网络越大
4. **降低维护成本**：映射更新可以由行业协会和咨询顾问共同贡献
5. **私有化需求**：中型制造企业的 IT 部门可以审查代码

### 5.2 开放边界

| 模块 | 许可 | 说明 |
|---|---|---|
| `belegt-dictionary` 数据点字典与模板映射 | CC BY 4.0 | 只发布题号和映射，不复制受版权保护的问卷原文（如 CDP）[需法务确认] |
| `belegt-calc` 计算库 | Apache-2.0 | 含方法论文档和测试向量；只内置开放许可的排放因子（如 EU CBAM 默认值、UBA）；商业因子库（如 ecoinvent）只提供适配器，用户自带许可证 |
| `belegt-io` 解析与原格式回填 | Apache-2.0 | Excel、PDF、Word、CMRT 等 |
| `belegt-connectors` MCP 连接器 SDK | Apache-2.0 | 社区可以为本地 ERP 写连接器 |
| `belegt-supplier` 供应商端 | Apache-2.0 | 多语言，可自托管，免费 |
| `belegt-core` 编排 + 证据图 + 守卫 | AGPL-3.0 | 可以自部署；防止云厂商不回馈就直接托管 |
| 评测基准 | CC BY 4.0 | 公开模板加合成数据 |
| **商业闭源** | — | 托管 SaaS、多租户与 SSO、门户自动化脚本库、法规雷达订阅源、已核验的字典更新 SLA、客户订阅网络与核查复用 |

### 5.3 治理

- 字典变更走 RFC 流程，设维护者名单，按季度发版并给出迁移说明
- 邀请行业协会、核查机构、咨询公司成为贡献方
- 与 PACT 技术规范、Eclipse Tractus-X（Catena-X 开源参考实现）对齐，避免另起标准
- 设安全漏洞披露流程，并做依赖许可审查

## 6. 功能需求（P0 = MVP）

**6.0 Agent 基础设施（新增）**
- FR-001（P0）持久化工作流：问卷级状态机，支持断点续跑和重放
- FR-002（P0）证据图和数据契约，带 schema 校验与版本
- FR-003（P0）守卫：隔离区、工具白名单、预算上限、全链路追踪
- FR-004（P0）Agent 评测集与 CI 回归
- FR-005（P1）MCP 连接器规范，模型提供方可配置

**6.1 收件与解析**
- FR-101（P0）接入邮箱，识别 Excel / PDF / Word 问卷，提取截止日期
- FR-102（P0）题目映射到字典并给出置信度；低置信度题目转人工
- FR-103（P1）客户门户任务抓取，先做最常见的 3 个门户 [待调研]

**6.2 数据与计算**
- FR-201（P0）导入历史答卷，建成答案库并写入证据图
- FR-202（P0）文档提取：账单、证书、材质证明、安全数据表，并定位到原文
- FR-203（P1）ERP 连接器（MCP），优先做试点客户在用的系统
- FR-204（P1）PCF 与 Scope 1/2 计算服务，因子库版本可追溯
- FR-205（P1）CBAM 隐含排放计算，测算“默认值和实际值的成本差”

**6.3 上游追数**
- FR-301（P1）多语言请求模板，附供应商端链接
- FR-302（P1）自动催办，审核回收数据的合理性（隔离区）
- FR-303（P2）EUDR 地理坐标与供应商声明管理

**6.4 质量与审批**
- FR-401（P0）每个答案都带证据链；数字缺少引用就拒绝写入
- FR-402（P0）跨客户、跨时间的一致性审计
- FR-403（P0）风险分级审批，一键批量批准
- FR-404（P0）证书和数据有效期预警

**6.5 交付**
- FR-501（P0）按原格式回填并导出
- FR-502（P1）浏览器 Agent 在沙箱里提交到门户，仅在批准后执行
- FR-503（P2）Catena-X / PACT 数据交换，输出电池护照字段

**6.6 网络化（V2）**
- FR-601（P2）客户订阅：经供应商授权，客户通过 API / A2A 拉取最新数据
- FR-602（P2）一次核查、多方复用

**6.7 开源（新增）**
- FR-701（P0）字典公开仓库、贡献指南、RFC 流程
- FR-702（P0）计算库可以独立运行，带测试向量
- FR-703（P1）供应商端可自托管，支持多语言
- FR-704（P1）一键私有化部署（docker compose / Helm），支持本地模型

## 7. 非功能需求

- 数据放在欧盟境内，可选私有化部署；每个客户的数据访问可以单独授权
- 计算可复现：同样的输入、因子版本和方法论版本，输出一致
- 数字类答案不允许模型生成（在 FR-401 层面强制）
- 可观测：每一步都有追踪和成本记录，可以按问卷导出审计包
- 模型无关：任一 Agent 都能切换模型而不改业务逻辑
- 界面支持德语和英语；上游沟通支持多语言

## 8. 异常与边界情况

| 情况 | 处理方式 |
|---|---|
| 没有数据 | 标注“估算”或“暂无”，不编造，给出补数路径 |
| 不同客户要求的方法论冲突 | 按客户分别计算，记录口径差异 |
| 上游供应商不回复 | 升级催办，测算默认值成本，提醒采购介入 |
| 问卷里有法律承诺条款 | 强制人工确认，并标出风险 |
| 提示词注入 | 只在隔离区处理，无工具可调，不能触发任何操作 |
| Agent 超预算或循环 | 守卫中止，保存状态，转人工 |
| 模型升级导致结果漂移 | 必须通过 CI 黄金集才能上线 |

## 9. 指标

- **北极星**：每月通过审批并提交的问卷数
- **效率**：单份问卷人工时长、自动预填率、响应天数
- **质量**：冲突拦截数、提交后被退回的比例
- **Agent**：各 Agent 准确率、转人工率、单份问卷成本、首稿时长
- **开源 / 网络**：字典外部贡献占比、供应商端活跃数、自托管装机量、开源到付费的转化率
- **业务**：CBAM 默认值比例、因合规数据赢得或保住的订单（客户自报）

## 10. 商业模式 [待验证]

- **免费**：开源全栈自部署；供应商端永久免费
- **SaaS 订阅**：按活跃客户数 / 问卷量分档，含托管、门户自动化、法规雷达
- **附加模块**：CBAM 追数按供应商数量计费
- **企业版**：私有化部署支持、SSO、SLA
- **V2 网络**：向调取数据的客户方收费，形成双边网络

## 11. 版本规划

| 阶段 | 范围 |
|---|---|
| MVP（0–3 个月） | 编排 + 证据图 + 守卫；收件解析、历史答案库、文档提取、一致性审计、回填导出、审批；**开源字典 v0.1 和计算库** |
| V1（3–6 个月） | ERP MCP 连接器、PCF / Scope 计算、CBAM 追数和开源供应商端、门户自动化、私有化部署（赶在 2027 年 9 月 CBAM 年度申报之前 [需核实]） |
| V2（6–12 个月） | 客户订阅网络（A2A）、Catena-X / PACT、电池护照、EUDR 模块、社区治理成型 |

## 12. 风险与验证

| 风险 | 应对 |
|---|---|
| **CBAM 简化后新增年进口 50 吨的豁免门槛** [需核实]，部分目标客户可能无需申报 | 访谈前先核实目标客户的年进口量；即使豁免，主机厂仍会索要碳数据，可以把重心放在 PCF |
| VSME 成为价值链数据上限 [需核实] | 利好：把 VSME 作为字典的第一优先模板 |
| EUDR 再度推迟 [需核实] | 维持在 V2，不提前投入 |
| ESG 大平台向下延伸 | 开源字典成为标准、免费供应商端和双边网络 |
| 开源被竞争对手直接复用 | 护城河在网络、已核验数据和托管运营；核心层用 AGPL |
| 多 Agent 成本和延迟失控 | 确定性优先、按 Agent 设预算、缓存、小模型分流 |
| 模型漂移导致质量下降 | 黄金集 CI，模型版本固定 |
| ERP 数据质量差 | 先从文档和历史答卷做起，ERP 是增强项 |
| 数据准确性的责任 | 证据链、人工批准、“只准备、不担保”；开源许可里写明免责 |
| 问卷原文版权 | 字典只发布映射，不发布原文 |
